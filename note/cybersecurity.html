OSPF 路由協定入門

從基本原理、鄰居關係到路由表， 理解 OSPF 如何讓路由器學習並選擇最佳路徑。

學習主題：CCNA / Routing 閱讀時間：約 8 分鐘

本篇目錄

01. OSPF 是什麼 02. 核心觀念 03. 鄰居建立 04. 設定範例 05. 驗證指令 06. 常見問題 07. 重點整理

01. OSPF 是什麼？

OSPF（Open Shortest Path First）是一種 Link-State（鏈路狀態）內部閘道路由協定， 用來交換同一個自治系統（AS）內的路由資訊。

OSPF 會透過鏈路狀態資訊建立拓樸資料庫， 再使用 SPF（Shortest Path First）演算法計算路徑， 並將選出的路由放入路由表。

核心觀念

OSPF 不是單純比較跳數，而是依據介面 Cost 計算路徑總成本。一般情況下，會選擇總 Cost 較低的可用路徑。

02. 核心觀念

Link-State Database（LSDB）

路由器透過 LSA（Link-State Advertisement） 傳遞鏈路狀態資訊，並據此建立 LSDB。 在相同區域內，路由器會維護一致的區域拓樸資訊。

SPF 演算法

OSPF 使用 Dijkstra SPF 演算法，以自身為起點， 根據鏈路 Cost 計算到其他目的地的最佳路徑。

Area 與 Area 0

OSPF 可將網路劃分為多個區域，以利管理與控制 拓樸資訊的傳播。多區域 OSPF 的骨幹區域是 Area 0，其他一般區域通常需要透過它連接。

Router ID

Router ID 是用來識別 OSPF 路由器的 32 位元識別值， 通常以 IPv4 點分十進位格式表示，例如 1.1.1.1。 它不必是實際可路由的介面 IP。

Cost

Cost 是 OSPF 路徑選擇的重要依據。 Cisco 設備常見的預設參考頻寬為 100 Mbps， 實際計算方式可能因平台及設定而異。 高速介面可能因預設參考頻寬不足而出現相同 Cost， 因此實務上應確認參考頻寬設定。

03. OSPF 鄰居如何建立？

兩台路由器要建立 OSPF 鄰居關係，通常需要確認：

  1. 介面正常運作，且能進行雙向 IP 通訊。
  2. 位於同一條鏈路上的 OSPF 設定與 Area 相符。
  3. Hello 與 Dead 計時器等必要參數相容。
  4. 驗證方式、驗證金鑰等設定相容（若有啟用）。
  5. 網路類型及其他鄰居形成條件符合要求。

在廣播型網路中，OSPF 可能會選出 DR（Designated Router） 與 BDR（Backup Designated Router），以減少鄰接關係數量。 但並非所有網路類型都會選舉 DR/BDR。

注意

鄰居狀態達到 Full 不代表所有路由一定都能正確學習； 仍須檢查 LSDB、路由表、路由過濾與介面狀態。

04. Cisco IOS 設定範例

假設 R1 的 LAN 網段為 192.168.1.0/24， 與另一台路由器互連的網段為 192.168.12.0/30。 以下示範在 R1 啟用單一 Area 0 的 OSPF。

設定 OSPF

R1(config)# router ospf 1
R1(config-router)# router-id 1.1.1.1
R1(config-router)# network 192.168.1.0 0.0.0.255 area 0
R1(config-router)# network 192.168.12.0 0.0.0.3 area 0

這裡的 1 是本機的 OSPF process ID， 在 Cisco IOS 上主要用於本機識別程序， 不要求鄰居使用相同數值。

0.0.0.255 與 0.0.0.3 是 wildcard mask， 分別對應 /24 與 /30 的網路範圍。 network 指令用來選取符合條件的介面， 並在指定的 Area 啟用 OSPF。

設定完成後的檢查

請先確認介面 IP、子網路遮罩與連線正常， 再查看鄰居狀態及 OSPF 學到的路由。

05. 常用驗證指令

查看 OSPF 鄰居

R1# show ip ospf neighbor

檢查鄰居 Router ID、狀態與所屬介面。 在需要完整鄰接關係的情境中，可確認狀態是否達到 Full。

查看 OSPF 資訊

R1# show ip ospf
R1# show ip ospf interface brief

檢查 Router ID、Area、介面參與情況及相關計時器。

查看 OSPF 路由

R1# show ip route ospf
R1# show ip protocols

在 Cisco 路由表中，OSPF 學到的路由通常以 O 標示；跨區域路由常見 O IA，外部路由則可能顯示 O E1 或 O E2。

06. 常見問題排查

問題一：沒有建立鄰居

檢查方向： 介面狀態、IP 網段、Area、Hello/Dead 計時器、 驗證設定及 OSPF 是否有啟用在正確介面。

問題二：鄰居卡在 EXSTART / EXCHANGE

檢查方向： MTU 不一致是常見原因之一，也應檢查資料庫交換、 鄰接狀態及相關日誌。

問題三：鄰居已建立，卻沒有預期路由

檢查方向： 確認網段是否被納入 OSPF、LSDB 是否存在對應資訊、 是否有路由過濾，以及路由是否被其他路由來源取代。

07. 重點整理

  • OSPF 是 Link-State 內部閘道路由協定。
  • LSA 提供鏈路狀態資訊，LSDB 保存拓樸資料。
  • SPF 演算法依路徑 Cost 計算最佳路徑。
  • 多區域 OSPF 通常以 Area 0 作為骨幹區域。
  • 建立鄰居後，還要檢查路由表與實際連通性。
延伸練習

在模擬環境中配置兩台路由器， 觀察鄰居狀態、LSDB 與路由表的變化， 再嘗試修改 Cost，驗證路徑選擇結果。
